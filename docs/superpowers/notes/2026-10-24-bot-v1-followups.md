# bot-v1: решения исполнения и отложенное (2026-10-24)

План `docs/superpowers/plans/2026-10-23-subscriber-uniq-bot.md`, задачи 1–8 выполнены субагентами
(Sonnet-исполнитель + Sonnet-ревьюер на задачу), итоговое ревью ветки и один пакет правок F1–F9.
Ветка `bot-v1`, 270 тестов. Задачи 9 (подбор диапазонов) и 10 (VPS) ждут владельца.

## Решения, принятые по ходу (что будет, если решение неверно)

1. Задача 2 дописывает `clips` в `tests/conftest.py`. Цена ошибки — нулевая.
2. Счётчики рассылки в строку `broadcasts` пишет сама `send_broadcast`, колбэк админки только правит сообщение. Цена — лишняя запись в БД.
3. `nice -n 10` только на POSIX. Цена — локальный рендер на Windows с обычным приоритетом.
4. Работа в ветке `bot-v1` того же репозитория, без отдельного worktree. Цена — нулевая.
5. Итоговое ревью на Sonnet по указанию владельца, а не на самой сильной модели. Цена — тонкие ошибки могут дойти до приёмки.
6. Движку передаётся `PYTHONUTF8=1` (на консоли cp1251 он падает на эмодзи). Цена — нулевая.
7. `.gitattributes` с LF для sh/Dockerfile/yml/yaml/py/toml/md. Цена — шумный diff.
8. `env_ignore_empty=True` в Settings: пустой ключ в `.env` = значение по умолчанию. Цена — пустое значение молча становится дефолтом.
9. Слабую проверку в тесте ошибки движка (из плана) усилили до проверки хвоста stderr. Цена — нулевая.
10. «Один открытый заказ на человека» держит частичный уникальный индекс в БД, `create_order` бросает `ActiveOrderExists` (альбом из нескольких видео приходит параллельно). Цена — лишний индекс.
11. Если у заказа ещё нет id статус-сообщения, воркер шлёт новое. Цена — лишнее сообщение в редкой гонке.
12. `getFile`/скачивание/`sendDocument` ждут до 600 с (у aiogram по умолчанию 60 с, а файл до 200 МБ идёт дольше). Цена — зависшая отправка держит очередь до 10 минут.
13. Оставлены защита CSV от формул (апостроф перед `= + - @`) и зависимость `tzdata`. Цена — видимый апостроф у имён, начинающихся с `+`/`-`.
14. Бот не стартует без `BOT_TOKEN`, `CHANNEL_ID`, `CHANNEL_URL`, `ADMIN_IDS` и с неверным `TZ`; у Bot нет parse_mode по умолчанию. Цена — бот не запустится без канала.
15. Токен вычищается из текста ошибок заказа, уведомлений админам и логов (пути локального сервера Bot API содержат токен). Цена — нулевая.
16. Неверную строку README про `logout-cloud` исправили в общем пакете правок, без отдельного круга. Цена — нулевая.
17. Из `deploy.ps1` убраны общехостовые `docker image prune`/`builder prune` (они чистили бы кэш бота рилсов); чистятся только образы с меткой `app=uniqbot`. Цена — свои висячие образы иногда придётся чистить руками.
18. Перед перекодированием (поворот/HDR) кадр уменьшается до 1920 по большей стороне: 4K HDR с iPhone иначе съедает 900 с на 2 vCPU. Цена — ничего видимого (движок всё равно выдаёт 1080×1920).
19. Упавшая рассылка помечается `interrupted` со счётчиками, админ получает «Рассылка прервалась из-за ошибки…». Цена — один лишний текст.
20. В общий пакет вошли: полный текст `/privacy`, проверка `config/uniq.yaml` при загрузке, белый список расширений и контейнеров для входных файлов, дочерние процессы без секретов в окружении. Отложено (ниже): текст статуса после ошибки, проверка свободного места, бэкап `bot.db`, счётчик попыток, ограничение `-Test`, готовность bot-api. Цена — немного лишнего кода.
21. Найдено исполнителем задачи 8: у compose явное имя проекта `uniqbot`. По образцу Уникализатора оба проекта назывались бы `app`, и `--remove-orphans` задел бы бота рилсов.

## Перед первым деплоем (задача 10)

- `deploy.ps1 -Test` гоняет все тесты (в том числе рендеры) без ограничения ресурсов на общей VPS: запускать, когда бот рилсов простаивает.
- Docker-образ ещё ни разу не собирался: первая сборка на сервере. Если в Debian-ffmpeg нет `zscale`/`libx264`/`libx265` или uid 101 занят, сборка остановится до подмены (безопасно).
- Проверить руками: файл 150–200 МБ от начала до конца; перезапуск контейнера посреди рендера (заказ возвращается в очередь и заново скачивается по `file_id`); права на `/var/lib/telegram-bot-api/<token>/…` изнутри контейнера `bot`; `docker system df` до и после.
- `bot-api` пока на `:latest` — после первого деплоя закрепить digest (README, шаг 5).
- `depends_on` не ждёт готовности bot-api: первый старт может дать один рестарт и ложное «не запустился».
- После `logout-cloud` для отладки в облачном режиме нужен отдельный dev-бот, не боевой токен.

## Отложено (мелочи, на работу не влияют)

- Ошибка `finish_order(DONE)` после доставки оставляет заказ `processing` (и блокирует человеку новые заказы до рестарта; после рестарта результат придёт повторно).
- Нет повторной попытки при `RetryAfter`/сетевой ошибке на `send_document`; нет счётчика попыток для заказа, который роняет контейнер.
- Нет проверки свободного места перед рендером (диск общий с ботом рилсов) и бэкапа `bot.db` (`sqlite3 .backup` по расписанию).
- `probe_source` выдаёт «не видео» и на сбой самого ffprobe; `_run` наследует stdin; `__main__ render` с зашитыми 900 с.
- Устаревшая кнопка подтверждения рассылки отправляет последний пост; альбом в рассылке даёт несколько превью.
- Приглушённые короткие ролики, пришедшие как GIF, получают подсказку «пришли обычное видео».
- Падение задачи воркера только пишется в лог, без уведомления админу.
- Тестовые мелочи: тайминги `sleep` в двух тестах, `Barrier` без таймаута, `make_settings` в `test_app` не закрепляет `bot_api_url`.
